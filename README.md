# Bevy Project Wizard for RustRover

Adds **Bevy**, with its official project icon, to RustRover's **File → New → Project** dialog. The wizard uses RustRover's normal project name and location fields, then moves through **Project**, **Dependencies**, and **Review** pages. It offers a Bevy version, five project kinds, optional TiltUI features, and selectable crates from [Bevy Assets](https://bevy.org/assets/). Stable Bevy releases are shown by default; check **Allow release candidates (RC)** to include RC releases. The latest stable release stays selected until you choose another version. The Review page summarizes the selected options before project creation.

The wizard reads Bevy's minimum Rust version from crates.io and lists locally installed Rust toolchains with their compiler versions. It selects a compatible toolchain when available, and offers **Install Rust** or **Update stable** when the selected compiler is too old. Generated projects contain `rust-version` in `Cargo.toml` and a `rust-toolchain.toml` for the selected toolchain.

WASM projects include a Trunk browser shell. **Use Just** is optional and unchecked by default. When checked, the wizard looks for Just and shows its version with a green check. If Just is missing, choose **Install Just** and click the install button, or choose **Create justfile only**. Just projects include `just run` for desktop, `just web` for Trunk, and `just web-build` for the browser build. Without Just, the generated README provides copyable Cargo and Trunk shell commands. **Create Git Repository** creates a repository; its **Include .gitignore** option appears below it only when Git is selected. The ignore file excludes Rust build output, Trunk output for WASM targets, and local IDE files. Library and Blank projects also ignore `Cargo.lock`, while binary projects keep it. Blank and Library projects have no `justfile` or `src-ui` directory, and the wizard disables TiltUI and Just for those kinds.

When TiltUI is enabled, the Project page shows the chosen TiltUI version. Select another release from **TiltUI version**, or check **Allow TiltUI release candidates (RC)** to include compatible RC releases. The wizard checks crates.io for releases published for both `tilt-ui` and `tilt-ui-build`, then offers the versions maintained by this plugin; `0.1.0` is the default and `0.1.0-rc.2` is available with the RC checkbox. Review shows the chosen version. The generated project includes `src-ui/index.html`, a light-themed `main.component` welcome page, `build.rs`, and matching `tilt-ui` / `tilt-ui-build` dependencies pinned to that version. Its Rust state and HTML template demonstrate working `@use`, `@let`, `@if`/`@else`, `@match`, and `@for` directives. The welcome page stacks its GitHub, crates.io, and Bevy links vertically; link icons appear only when `tilt-icons` is selected. **Use Routing** adds Home and About pages, working navigation buttons, a router outlet, and a central `src-ui/routers.rs`. The maintained `TiltUiCompatibility` definition records the supported Bevy 0.19.x series and feature catalog for these releases. Bevy 0.19.1 requires Rust 1.95 or newer.

Selecting **Use TiltUI** opens a compact feature popup; **Choose TiltUI features…** reopens it. Features have titles and descriptions. Click a title to open the related crates' complete `README.md` files in tabs. The project reads the local TiltUI repository first and bundles a snapshot of the READMEs into the plugin for use elsewhere. Components, HTML, and CSS are included by the generated template; hot reload, Fluent localization, and icons are optional. Hot reload is disabled for both WASM project kinds and is omitted from their generated Cargo features.

The **Dependencies** page uses a Spring Initializr-style category column, searchable crate results, and a selected-crates tray with direct removal. Opening this page loads Bevy's asset catalog; no separate enable option is needed. Only assets tagged for the chosen Bevy release appear. The filter icon opens Bevy-tag and sort controls. Crate release versions, update times, and download counts come from crates.io. Click a blue crate title to read its complete README in the wizard's browser dialog; crates.io's JSON README pointer is followed to its full HTML content. Click the checkbox or any other part of a crate card as soon as it appears to select it. It checks immediately while the wizard verifies the package name and a release's Bevy dependencies in the background. The package name is confirmed through a direct crates.io link or a matching GitHub repository; if neither confirms it, the wizard follows GitHub repository redirects and offers published packages from the matching repository or closely matching names in a dropdown, with **Other…** for a custom package name. Reserved placeholders and unrelated search results are excluded; for example, Avian offers `avian3d` and `avian2d`. Use **Change package…** in the selected-crates tray for the same dropdown when an automatically detected name looks wrong; the chosen package is checked against crates.io and the selected Bevy release. A crate without a compatible published release is removed from the selection with an explanation. For Bevy 0.19, the wizard selects Lightyear 0.28.x. Both Bevy and verified community crate versions are pinned exactly. The Review page keeps each selected crate title visible; expand it to see the Cargo package name, release, catalog source, Bevy support, and name-verification method. Project creation rejects unverified names. A warning icon appears beside a crate name only when its package cannot be matched automatically and the package dropdown is needed; hover it for the Bevy Assets caveat. Review has no separate warning paragraph. The result list has its own large scroll area. If JCEF is unavailable, the README still renders inside the dialog using Swing's HTML viewer. Filters retain their selections while crate metadata refreshes. On the **Review** page, click a selected crate to open its README or **Edit selection…** to return to the catalog. The project, catalog, feature popup, selected-crate tray, and review content scroll with the pointer over their content. RustRover's Create button becomes enabled after the Review page is reached with valid settings.

The Bevy icon is from [Bevy's official branding assets](https://github.com/bevyengine/bevy/tree/main/assets/branding).

In a project with a `tilt-ui` Cargo dependency, the **TiltUI project setup** inspection highlights a missing `src-ui/index.html`, broken local stylesheet links, incomplete component HTML/CSS/Rust file triplets, a missing or incorrect `build.rs`, and `TiltUiPlugin` placed after `DefaultPlugins`. The editor offers quick fixes to create missing files while leaving existing code intact.

## Add a TiltUI component

In a TiltUI project, right-click a directory in the project tree and choose **New → Tilt Component**. The menu uses a clear, transparent TiltUI logo with an integrated green plus. Enter a lowercase name such as `example/example`; the wizard creates `example/example.component.html`, `.css`, and `.rs` beneath the selected `src-ui` directory. If a Rust `src` directory is selected, the same relative folder is created beneath `src-ui`. **Component** is the default type. RustRover refreshes its Cargo project after creating the files so the generated component module is discovered.

Choose **Routing** to create the same three files plus `example.route.rs`. The plugin imports the route in `src-ui/routers.rs` and adds a router outlet to the generated starter page if needed. If the wizard created a home route, additional routes are merged into its central registry. Otherwise the first route also handles `/`, so it is visible immediately; its named path is `/example/example`. The source code is organized into `catalog`, `project`, `wizard`, `component`, and `template` packages, with English JavaDocs on the main classes and methods.

## Edit TiltUI templates

In `*.component.html`, RustRover highlights and completes `@if`, `@else`, `@for`, `@match`, `@let`, and `@use` as TiltUI directives. The scanner respects nested directive blocks, comments, strings, event and bound attributes, interpolation, and incomplete expressions while typing. `@let` values and `@for` loop variables remain available only in their template scope. Inside `@use "..."`, completion lists Rust structs and enums exposed with `#[html_shared]` or `#[html_use]` from project sources such as `src` and `src-ui`. Qualified paths such as `bevy::` also offer Rust symbols from Cargo dependencies after RustRover syncs the workspace; TiltUI can bind only resources exposed to its runtime. Use `@use "crate::module::Profile" as profile;` to import one under an alias. Go to Declaration on the quoted type name opens its Rust declaration; Find Usages on that declaration includes the import. Event attributes complete `$set`, `$add`, `$sub`, `$min`, `$mul`, `$div`, `$clamp`, `$toggle`, and `$append` as inline actions. Hover over a directive or action for its signature and short description. Completion keeps the leading `@` or `$` when inserting an item.

The matching `name.component.rs` supplies template completion for `#[html_shared]` resources, `UiStore` types, their fields (including nested struct fields), `#[html_fn("name")]` handlers, and `#[html_method("name", "resource.method")]` methods. `@use` aliases provide field completion for exposed types declared in other project Rust files too. `@let` values and `@for` loop variables complete in expressions, and Rust `///` documentation on types, fields, and handlers appears on hover. Project components such as `app-header.component.html` are recognized and completed as `<app-header>` tags, with hover documentation from a leading HTML comment or a default description. TiltUI's `<tag/>` syntax is recognized as closed. Built-in widgets complete their supported static attributes, reactive `[property]` bindings, and enum values, with hover help and value validation for the selected `0.1.0` or `0.1.0-rc.2` release. Registered `#[html_fn]` handlers receive function coloring in event attributes; unresolved event names point to registration in the matching Rust file instead of a JavaScript file. Ordinary Rust locals are not exposed to TiltUI templates. Use **Go to Declaration** from a binding or event handler to open its Rust declaration; **Find Usages** on a Rust field or handler includes the corresponding HTML expressions. These editor features are scoped to `*.component.html` files.

TiltUI component stylesheets and CSS files under `src-ui` complete TiltUI properties and values alongside RustRover's standard CSS suggestions. Hover help covers filter effects, motion and layout declarations, and `tilt-icon:name@size` sources. The **TiltUI CSS values** inspection warns on parser-specific unsupported values such as `backdrop-filter: oil-paint(2)` or `effect-quality: ultra`; it only runs for maintained TiltUI releases.

Projects that enable the `tilt-icons` feature or depend on `tilt-ui-icons` get a **Tilt UI Icons** button on the right tool-window stripe. The button appears after Cargo imports or changes without reopening the project. Its catalog contains all 537 SVG icons from TiltUI's `examples/icons-catalog`, with search, category and size menus, 36 icons per page, a color picker canvas with hue, presets, Hex and RGB controls, a large preview, and a button that copies the selected `<icon name="..." size="32"></icon>` snippet. Menus close on outside clicks or Escape. The catalog follows RustRover's light or dark theme. The icon snapshot can be refreshed with `python3 scripts/sync_icon_catalog.py /path/to/tilt-ui src/main/resources/icon-catalog.json`.

## Try the plugin

Run `./gradlew runIde` to launch an isolated RustRover instance with the plugin installed. Open **File → New → Project → Bevy**, fill in the fields, and create a project. For a browser project, install the `wasm32-unknown-unknown` target and Trunk, then run `trunk serve --open` from the generated project directory.

Run `./gradlew test buildPlugin` to execute the generator tests and create `build/distributions/tilt-jetbrains-plugin-0.1.0.zip`. Before a release, run `./gradlew validateGeneratedProjects` to compare every offered TiltUI version with published crates.io metadata and check freshly generated stable desktop, RC desktop, and, when installed for the selected toolchain, WASM projects with Cargo. To install the ZIP in your regular RustRover instance, use **Settings → Plugins → ⚙ → Install Plugin from Disk**, select the ZIP, then restart RustRover.

Run `./gradlew javadoc` to generate the English API documentation in `build/docs/javadoc`. `./gradlew verifyPluginStructure verifyPluginProjectConfiguration` checks the plugin archive and JetBrains configuration.
