# TODO: TiltUI support in RustRover

This is the plugin backlog, based on the local TiltUI `0.1.0` workspace and its README, architecture docs, widget docs, and examples (reviewed 2026-10-05). The plugin already creates Bevy/TiltUI projects and components, offers basic template completion and navigation, and has an icon browser. Tasks below concern missing or incomplete IDE behavior. Keep TiltUI's own runtime backlog in its repository.

## P0 — Correctness and reliable editing

- [x] **Verify community crate identities before writing `Cargo.toml`.** Match a Bevy Assets crate to a published crates.io package through a direct crates.io link or the same GitHub repository. If that cannot be confirmed, offer packages from the linked repository (following GitHub renames) or closely matching names in a dropdown with **Other…** for a custom name, then verify the chosen package and release. Reserved placeholders and unrelated search results are excluded; Avian offers `avian3d` and `avian2d`. Review keeps each crate title visible and collapses its Cargo name, release, source, Bevy support, and verification method underneath. Project generation rejects unverified names.
- [x] **Keep generated projects aligned with released TiltUI versions.** `TiltUiCompatibility` owns the maintained TiltUI releases, Bevy series, Rust minimum, and published feature catalog. The wizard shows the selected TiltUI version, offers a manual version dropdown, and reveals compatible RC releases with a separate checkbox. It checks that both `tilt-ui` and `tilt-ui-build` publish the chosen release, pins both to it, and shows the choice in Review. `./gradlew validateGeneratedProjects` checks published metadata and runs Cargo checks for generated stable and RC desktop projects plus installed WASM targets. The maintained releases are `0.1.0` and `0.1.0-rc.2` for stable Bevy `0.19.x`.
- [x] **Add a TiltUI project inspection.** In projects with a `tilt-ui` Cargo dependency, the IDE reports a missing `src-ui/index.html`, broken local stylesheet links, incomplete `.component.html`/`.css`/`.rs` triplets, a missing or incorrect `build.rs`, and `TiltUiPlugin` placed after `DefaultPlugins`. Quick fixes create missing entry, stylesheet, build script, and companion files without replacing existing code.
- [x] **Parse template syntax with proper scopes.** `TemplateScanner` now scans HTML and TiltUI syntax with balanced delimiters and skips comments, quoted strings, and raw style/script content. It recognizes nested `@if`/`@else if`, `@match`, `@for (...; track ...)`, `@let`, interpolation, event/bound attributes, and unfinished expressions. Template locals are visible only after declaration and inside their blocks; completion, navigation, and highlighting use the parsed regions and scopes.
- [x] **Validate Rust bindings and inline actions accurately.** Rust PSI resolves `#[html_shared]`, `#[html_use]`, `#[derive(UiStore)]`, `#[ui_store(mutable)]`, `#[html_fn]`, and `#[html_method]`. The template inspection reports unknown handlers, methods, fields, and `$set`/`$add` targets without a mutable UI store; it recognizes `$event`, the built-in `i18n` root, template locals, and imported resources. Navigation reaches Rust declarations, and quick fixes create missing handler/method registrations, correct close field names, or make a UiStore mutable.

## P1 — Day-to-day authoring

- [x] **Put crate statistics in a right-aligned card footer.** Each crate is a bordered card with a README-linked title, a description capped at two lines, and a compact footer with Bevy support and downloads side by side at the bottom right. Downloads show an icon and count, an animated spinner while metadata loads, or `-` when unavailable; Bevy support appears as `Bevy: 0.19`. Late metadata updates already selected cards without changing their verified release.
- [x] **Group patch releases in the Bevy version filter.** Stable tags such as `0.19`, `0.19.1`, `^0.19`, and `^0.19.1` share the `Bevy 0.19` filter. `0.20` and release candidates have separate choices. The selected exact Bevy release must still satisfy each crate's original tag.
- [x] **Keep nested wizard scrolling predictable.** The scroll area under the pointer handles the wheel only while it can move in that direction. A nested area without a visible scrollbar, or one already at its edge, passes scrolling to the nearest outer scroll area.
- [x] **Complete the widget and attribute catalog.** `TiltWidgetCatalog` follows the published `0.1.0` and `0.1.0-rc.2` widget runtimes and offers tag-specific static and reactive `[property]` attributes, enum values, short hover documentation, and value validation for forms, inputs, sliders, dialogs, toasts, tooltips, icons, and the other built-in aliases. Unknown releases do not receive release-specific suggestions.
- [x] **Support TiltUI CSS in the editor.** CSS completion and hover help cover `background-filter`, `backdrop-filter`, `animated-filter`, `effect-quality`, `border-brush-strength`, `tilt-icon:`, and supported motion and layout values. A TiltUI-only inspection checks parser-specific values, skips CSS comments and strings, and leaves standard CSS support to RustRover. The catalog is gated by the pinned TiltUI release.
- [x] **Make UI asset paths navigable.** Completion, Go to Declaration, and missing-file diagnostics cover entry-document stylesheets, CSS image URLs, HTML image/SVG paths, theme and locale directories, Fluent catalogs, Rust include paths, and route module paths. Paths use the configured UI source root, including custom roots; the project inspection follows that root too.
- [x] **Add safe rename support across component files.** IDE Rename updates a component's HTML/CSS/Rust triplet, matching route file, custom tags, component IDs in routes, and module paths together. Renaming Rust fields and handlers updates matching template references; handler registration strings follow when they use the Rust function name, while explicit aliases stay stable. These references take part in Rename preview and Find Usages.
- [ ] **Add Fluent assistance when the `fluent` feature is enabled.** Complete `i18n.key` and Fluent attributes from `.ftl` files, navigate from a template use to its message, and report missing keys per configured locale. Offer a starter `locales/en-US.ftl` and wiring when Fluent is selected in the project wizard. Suppress these inspections when the feature is absent.
- [ ] **Improve route creation and navigation.** Offer transient `.route(...)`, eager retained `load!(...)`, and lazy retained `lazy!(...)` choices in the New Component flow. Complete route paths and component IDs, navigate from `<router-outlet>`/route references to `routers.rs` and the target component, and check duplicate or unreachable paths. Use TiltUI's routing showcase as the behavior reference.
- [ ] **Connect the icon browser to the editor.** Insert the selected `<icon ...>` tag or `tilt-icon:...` value at the caret, complete icon names and supported sizes, and navigate to the icon documentation. Warn when `tilt-icons` is not enabled and offer a Cargo feature fix. Refresh the bundled catalog from the versioned `tilt-ui-icons` source rather than relying only on the showcase snapshot.

## P2 — Workflow and maintenance

- [ ] **Add an actual TiltUI run/preview workflow.** Provide run configurations for desktop (`cargo run`) and browser (`trunk serve`) projects, show build and runtime errors in RustRover, and use TiltUI hot reload when supported. Preview the real Bevy application rather than rendering component HTML as a browser page, because TiltUI's widgets and CSS are implemented by its runtime.
- [ ] **Offer useful component starters.** Add optional templates for a form, dialog, localized page, themed page, and loading state using the APIs demonstrated by TiltUI's component showcase. Keep the plain Component and Routing choices simple, and generate only the files and Cargo features each starter needs.
- [ ] **Automate compatibility checks.** Test the plugin against the supported RustRover build range, current TiltUI release metadata, desktop/WASM generated projects, and representative templates from TiltUI's `basic`, `routing`, `component-showcase`, and `css-showcase` examples. Run plugin verification before packaging a release; update the completion catalog when a TiltUI API changes.
